# ตั้งค่าติดตามงาน กอจ.

ข้อสรุปบริการและสิทธิ์อยู่ใน [ADR 0026](adr/0026-koj-tracks-external-documents-and-status-changes.md) หน้าจัดการคือ `/koj/` อยู่ในเมนูแอดมินเท่านั้น (เจ้าของตัดสิน 28 ต.ค. 2569) แอดมินเพิ่มหรือแก้แหล่งข้อมูลและสั่งอ่านใหม่ได้ พนักงาน กอจ. รอรอบอ่านทุกชั่วโมง

1. อัปเดต dependencies จาก `uv.lock` และรัน migration `0069_koj_tracking` หลัง migrations ก่อนหน้า รัน `python manage.py seed_line_flows --division กอจ. --replace-draft` เพื่อเพิ่มหรือแทนร่าง Flow เฉพาะ กอจ. โดยไม่เปลี่ยนรุ่นเผยแพร่ ร่าง `koj-tracking` แสดงขั้นเลือกอุปกรณ์ อุปกรณ์ย่อย พิมพ์ชื่อ และเลือกบริการเป็นกล่องบนผืนผ้าใบ แอดมินแก้ข้อความและชื่อปุ่มได้ แต่ละบริการจบที่กล่อง “ติดตามงานต้นทาง กอจ.” ซึ่งตั้ง `equipment` กับ `service` ไว้ ทางรายการติดตามใช้ `service=watches` ปุ่มในแชตยังเป็นการ์ดเดิมจนแอดมินกดเผยแพร่ร่างนี้
2. ผู้ดูแลเซิร์ฟเวอร์ตั้ง `KOJ_GOOGLE_CREDENTIALS_FILE` ให้ชี้ไฟล์ service account JSON ที่เก็บนอก repository และอ่านได้เฉพาะบัญชีรันแอป หากใช้ container ต้อง mount ไฟล์แบบอ่านอย่างเดียวและตั้งตัวแปรใน container ของ worker ด้วย
3. เปิด Google Sheets API ของ service account แล้วให้เจ้าของชีทแชร์แบบ Viewer เฉพาะชีทที่อนุญาตกับอีเมล service account ไม่ต้องเปิด public หรือให้สิทธิ์เขียนชีท
4. แอดมินเปิด `/koj/` จากเมนูแอดมิน เพิ่มแหล่งข้อมูล ใส่รหัสชีท ชื่อแท็บ บริการ อุปกรณ์ และจับคู่หัวคอลัมน์ ข้อมูลเริ่มแถวแรกเป็นหัวคอลัมน์ ใช้รหัสแถวถาวรที่ไม่ซ้ำ เลขเอกสารซ้ำได้ รหัสแถวห้ามใช้ลำดับแถวที่เปลี่ยนตามการเรียง หนึ่งแหล่งรับไม่เกิน 20000 แถวและ 20 MB หากเกินจะรายงานข้อผิดพลาดและรักษาข้อมูลรอบก่อน โดยไม่ตัดข้อมูลเงียบ ๆ
5. ตั้งคอลัมน์เขตและตารางจับคู่กับเขตในระบบ หากชีทมีหลายชนิดอุปกรณ์ เช่น LBS และ RMU ให้เลือกคอลัมน์อุปกรณ์และจับคู่แต่ละค่า ตั้งสถานะจบงานและช่องทางติดต่อ
6. กด "อ่านข้อมูลใหม่ตอนนี้" แล้วดูเวลาข้อมูลล่าสุดและผลการอ่าน ตรวจแถวที่ยังจับคู่เขตไม่ได้ก่อนเปิดใช้งาน แหล่ง CSV ใช้นำเข้าไฟล์ UTF-8 ที่มีหัวคอลัมน์เดียวกันได้
7. ในหน้าบัญชี LINE ของคนนั้น (หรือหน้าบัญชีเจ้าหน้าที่) เลือกชุดรับแจ้ง มค., ซจ. หรืออุปกรณ์อื่น ให้บัญชีนั้นมีสิทธิ์ กอจ. และเชื่อม LINE ก่อน รับหลายชุดหรือเลือกหลายคนในชุดเดียวกันได้

worker `run_worker` รันตัวอ่าน กอจ. ในเธรดแยก จึงไม่ให้การอ่านชีทชะลอแชต การสั่งอ่านใหม่ใช้คิวเดียวกับรอบรายชั่วโมงและล็อกแหล่งข้อมูลกันอ่านทับกัน การส่ง LINE ใช้ outbox การ retry และงบข้อความเดิม ต้องเปิดการส่งออกและ push ตามการตั้งค่าสภาพแวดล้อมก่อนใช้งานจริง

ผู้แจ้งกดเมนู กอจ. เลือกอุปกรณ์/บริการ แล้วพิมพ์เลขเอกสาร เมื่อพบงานให้กดติดตามการเปลี่ยนสถานะ ผู้แจ้งไม่ได้รับ push ระบบแจ้งงานที่เปลี่ยนตอนผู้แจ้งทักมาครั้งถัดไป ผู้รับแจ้งฝั่งเจ้าหน้าที่ได้ push ตามเดิม ประวัติและรายการที่จบแล้วอยู่ในรายการติดตาม กอจ. ทั้งหมดนี้ติดตามงานต้นทาง ไม่สร้าง `Case` หรือร่างเบิก/คืน

ชุดทดสอบ `operations.tests.test_m17_koj_tracking` ตรวจการค้นหลายแถว การจำกัดเขต เลขมีจุด การสมัคร/เลิกติดตาม การเปลี่ยนสถานะ การส่งซ้ำ สิทธิ์ผู้รับ งบข้อความ การ refresh และการเผยแพร่ Flow โดยใช้ข้อมูลจำลองและ mock เครือข่าย เก็บชีทจริงไว้ภายในหน่วยงานได้

## ผลตรวจ local

ชุดตรวจต่อไปนี้ผ่านรวม **137 กรณี**:

```text
operations.tests.test_m17_koj_tracking
operations.tests.test_m14_kcw_menu
operations.tests.test_m16_line_flows
operations.tests.test_m04_orchestration
operations.tests.test_m03_line
operations.tests.test_m13_staff_chat
```

Ruff check/format, Django system check, migration drift check, JavaScript syntax และ `git diff --check` ผ่าน ตรวจหน้าตั้งค่าแหล่งข้อมูลกับชุดรับแจ้งบนคอมและมือถือด้วย HTML ที่เรนเดอร์จาก Django และข้อมูลจำลองแล้ว ปุ่ม refresh และทั้งสามชุดรับแจ้งแสดงบนมือถือได้โดยไม่ทำให้หน้าล้นด้านข้าง

ชุดทดสอบทั้งระบบรวมงาน กคว. ผ่านครบ 1125 กรณี (28 ต.ค. 2569)

การตรวจรอบนี้ใช้ฐานทดสอบแยกจากฐานทำงานปกติ ไม่ได้เปิดชีทลับ ส่ง LINE จริง หรือ deploy การเปิดใช้งานต้องรัน migration/seed รวมกับงาน กคว. แล้วให้ผู้ดูแลตั้งแหล่งข้อมูล สิทธิ์อ่านชีท ผู้รับแจ้ง และงบ push ภายในหน่วยงาน
