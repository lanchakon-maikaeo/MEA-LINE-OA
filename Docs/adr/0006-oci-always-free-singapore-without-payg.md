# ใช้ OCI Always Free ที่ Singapore โดยไม่อัปเกรด Pay As You Go และให้คนสั่ง deploy บนเครื่อง

ผู้ใช้ยืนยันวันที่ 8 ตุลาคม 2569 (M12 Q1–Q15) ว่า staging และ production อยู่บน OCI tenancy แยกของโครงการ home region **Singapore** (เลือกครั้งเดียว เปลี่ยนไม่ได้) และ**ไม่อัปเกรดเป็น Pay As You Go** บัตรใช้ยืนยันตัวตนตอนสมัครเท่านั้น ต่างจาก E.2.1 เดิมที่จะอัปเกรดเพื่อกันเครื่องถูกยึดคืนเมื่อว่าง เอกสาร Oracle นับเครื่อง A1 ว่าว่างเมื่อ CPU, network **และหน่วยความจำ** ต่ำกว่า 20% ตลอด 7 วัน ระบบนี้ใช้หน่วยความจำราว 70–80% ของเครื่องตลอดเวลาจึงไม่เข้าเกณฑ์ บัญชีที่ไม่อัปเกรดจะไม่ถูกเก็บเงินแม้สร้างของเกินโควตา (การสร้างจะถูกปฏิเสธแทน) ผลข้างเคียงคือ Object Storage เป็น 20 GB รวมทุก tier จึงเก็บทุกอย่างใน Standard

GitHub ของโครงการเป็นแผนฟรี repo private ซึ่งตั้งกันแก้ main และบังคับผู้อนุมัติก่อน deploy ไม่ได้ จึงให้ CI ทำแค่ build ครั้งเดียว สแกน และส่ง image ขึ้น OCIR ส่วนการ deploy คนที่มีสิทธิ์บนเครื่องสั่ง `faoj deploy <digest>` ผ่าน OCI Bastion หลังบันทึกการอนุมัติ CI ไม่ถือสิทธิ์เข้าเครื่องหรือฐานข้อมูล ผู้ช่วยพัฒนามีเพียง key อ่านอย่างเดียว คำสั่งที่สร้าง แก้ หรือ deploy เจ้าของบัญชีเป็นคนรันเสมอ

## Considered Options

- **อัปเกรด PAYG ตามแผนเดิม:** ไม่เลือก ผู้ใช้ต้องการให้บัตรไม่มีทางถูกเก็บเงิน และเหตุผลเดิม (idle reclaim) ใช้ไม่ได้กับเครื่องที่ใช้หน่วยความจำเกิน 20% ข้อเสียที่ยอมรับ: มีรายงานว่าบัญชี PAYG ได้เครื่อง A1 ง่ายกว่าเมื่อ region เต็ม ถ้าสร้างเครื่องไม่ได้จะกลับมาตัดสินใหม่
- **Tokyo/Osaka:** ไม่เลือก ไกลกว่า และข้อมูลก็อยู่นอกประเทศเช่นกัน
- **VM ขององค์กร:** ไม่เลือกตอนนี้ ต้องขอ IT และเปิด DMZ ให้ LINE เรียกเข้ามาได้ stack ออกแบบให้ย้ายได้ (RB08)
- **อัปเกรด GitHub ให้ CI deploy เอง:** ไม่เลือก มีค่าใช้จ่าย และตอนนี้มีนักพัฒนาคนเดียวจึงบังคับผู้อนุมัติแยกไม่ได้จริง

## Consequences

- เปลี่ยน home region ภายหลังต้องสร้าง tenancy ใหม่และย้ายข้อมูลด้วย backup/restore
- ก่อนเก็บข้อมูลผู้ใช้จริง เจ้าของข้อมูลต้องรับรองการเก็บที่ Singapore (G02)
- ทุก deploy มีคนรับผิดชอบหนึ่งคนบนเครื่องพร้อมข้อความอนุมัติใน history ของ release
- ถ้า A1 ใน Singapore เต็มตอนสร้างเครื่อง ให้ลองใหม่ภายหลัง หรือทบทวนการอัปเกรด PAYG กับผู้ใช้
