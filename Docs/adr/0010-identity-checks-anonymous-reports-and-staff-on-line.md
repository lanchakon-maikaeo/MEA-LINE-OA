# ยืนยันตัวตนด้วยทะเบียนพนักงาน แจ้งแบบไม่ระบุตัวตนได้เฉพาะปัญหา/ข้อเสนอแนะ และเจ้าหน้าที่ใช้ LINE ได้

ผู้ใช้ตอบคำถามวันที่ 10 ตุลาคม 2569 ไว้ดังนี้

- Q1: เบิกหรือคืนของต้องยืนยันตัวตน ด้วยรหัสพนักงานที่ตรงฐานข้อมูล หรือทางอื่นเสมอ ไม่ fix ทางเดียว แจ้งปัญหา/ข้อเสนอแนะยืนยันตัวตนก็ได้หรือไม่ระบุตัวตนก็ได้ แต่ต้องเก็บตำแหน่ง
- Q3: ถ้ารหัสพนักงานอยู่ในฐานข้อมูลและพิสูจน์ได้จริง ให้อนุมัติอัตโนมัติและเก็บ audit log
- Q5: เด้งเฉพาะเรื่องสำคัญ ไม่ให้รก
- Q6: งบข้อความเจ้าหน้าที่ 220 ต่อเดือน ปรับได้
- Q7: เจ้าหน้าที่ทำงานและตอบผู้แจ้งใน LINE ได้ แต่ต้องเป็นส่วนตัวและไม่หลุด
- Q8: ผอ.แจ้งในนามกองได้
- LINE เดียวต้องเป็นได้ทั้งคนสั่งงานและผู้แจ้ง (ผอ.ฝอจ.)
- ข้อความที่บอทตอบใช้แนว /humanizer

**ทะเบียนพนักงาน:** แอดมินนำเข้า CSV โดยค่าที่ใช้ยืนยัน (เช่น วันเกิด) เก็บเป็น HMAC ของค่าที่ปรับรูปแล้วเท่านั้น ไม่มีใครเปิดดูค่าจริงได้ การตรวจต้องตรงทั้งรหัสพนักงาน ค่ายืนยัน และเขต (เมื่อทะเบียนระบุเขต) ผิดได้ 3 ครั้งต่อบัญชี LINE ต่อวัน audit บันทึกเฉพาะผลผ่าน/ไม่ผ่าน ไม่บันทึกค่าที่พิมพ์

**ตัวเลือกระบบ (ค่าเริ่มต้นคือค่าที่ปลอดภัย):**

| ตัวเลือก | ค่าที่เลือกได้ (ค่าเริ่มต้นอยู่หน้าสุด) |
| --- | --- |
| การยืนยันตัวตนตอนลงทะเบียน | ให้คนอนุมัติทุกคำขอ / ตรวจรหัสพนักงานแล้วให้คนอนุมัติ / ตรวจแล้วระบบอนุมัติเอง |
| ตำแหน่งผู้ลงทะเบียน (เลิกใช้ 31 ต.ค. 2569 การลงทะเบียนไม่ถามตำแหน่งแล้ว) | ไม่ถาม / ถามแต่ข้ามได้ / ต้องส่ง |
| ชื่อที่พิมพ์ตอนลงทะเบียน (เพิ่ม 11 ต.ค. 2569) | ต้องมีทั้งชื่อและนามสกุล / รับตามที่พิมพ์ |
| แจ้งแบบไม่ระบุตัวตน | ปิด / เปิด |
| จำนวนเรื่องไม่ระบุตัวตนต่อวัน | 3 / 5 / 10 |
| วิธีเชื่อม LINE ของเจ้าหน้าที่ | รหัสจากเว็บ / รหัสจากเว็บหรือรหัสพนักงาน |
| สิ่งที่เจ้าหน้าที่ทำได้ใน LINE | ดูอย่างเดียว / ดูและทำบางขั้น |
| งบข้อความเจ้าหน้าที่ต่อเดือน | 220 / 100 / 50 / 0 |

คนที่ไม่มีรหัสพนักงานหรือตรวจไม่ผ่าน เลือก "ใช้วิธีอื่น" ให้คนอนุมัติได้เสมอ

**ชื่อตอนลงทะเบียน** (ผู้ใช้ 11 ต.ค. 2569 "ปรับที่ยังปรับต่อได้": คำทักทายเคยกลายเป็นชื่อ):
- ค่าเริ่มต้นไม่รับคำทักทาย คำถาม คำขอ ข้อความที่มีตัวเลข และคำเดียวเป็นชื่อ บอทถามใหม่พร้อมตัวอย่าง คำถามที่ตรงคลังคำตอบได้คำตอบก่อน (ADR 0012)
- "ผมชื่อ..." ตัดคำนำออก
- ตอนเลือกเขตมีปุ่ม "แก้ชื่อ" เสมอ พิมพ์แทนการเลือกเขตได้รายการเขตอีกครั้ง ไม่เริ่มลงทะเบียนใหม่

**การอนุมัติอัตโนมัติ** ทำด้วยกฎ (ตรงทะเบียน + ค่ายืนยัน + เขต) ไม่ใช้ LLM ตัดสิน เพราะข้อความผู้ใช้อาจหลอกโมเดลได้ (ADR 0001, 0002) บันทึกเป็นการตัดสินของบัญชี `system` ในชื่อ `registration.auto_approved` พร้อมรหัสพนักงานที่ตรง

**ผู้แจ้งไม่ระบุตัวตน:**
- เป็นผู้แจ้งพิเศษหนึ่งรายต่อบัญชี LINE ไม่มีชื่อ ใช้เขต "ไม่ระบุเขต" (D00)
- ส่งได้เฉพาะเรื่องแจ้งปัญหา/ข้อเสนอแนะ และจำกัดจำนวนต่อวัน (31 ต.ค. 2569 เลิกขอตำแหน่ง เดิมต้องมีตำแหน่ง)
- เจ้าหน้าที่เห็นแค่ "ไม่ระบุตัวตน" บัญชี LINE ยังเป็น "ยังไม่ลงทะเบียน" จึงเบิกหรือคืนของไม่ได้

**เจ้าหน้าที่ใน LINE:**
- **การเชื่อม:** บัญชีเจ้าหน้าที่หนึ่งบัญชีเชื่อม LINE ได้หนึ่งบัญชี ด้วยรหัส 6 หลักจากหน้า "บัญชีของฉัน" (อายุ 10 นาที ใช้ครั้งเดียว เก็บเป็น hash ผิดได้ 5 ครั้งต่อวัน) หรือด้วยรหัสพนักงานกับค่ายืนยัน เมื่อบัญชีเจ้าหน้าที่มีรหัสพนักงานนั้น
- **บทบาทคู่:** LINE เดียวกันยังเป็นผู้แจ้งได้ สิทธิ์ของสองฝั่งแยกกัน
- **ระงับบัญชี:** เมื่อบัญชีเจ้าหน้าที่ถูกระงับ การเชื่อมหายทันที
- **ความเป็นส่วนตัว:**
  - ข้อความเด้งมีแค่เลขเรื่อง กอง และสิ่งที่เกิด ไม่มีชื่อหรือข้อความของผู้แจ้ง เพราะขึ้นบนหน้าจอล็อก
  - รายละเอียดดูได้เมื่อกดเท่านั้น ส่งเป็นข้อความตอบกลับในแชต 1:1 หลังตรวจสิทธิ์ซ้ำ
  - ปุ่มผูกกับบัญชี LINE นั้นและหมดอายุ
  - ทุกการกระทำผ่าน `services.perform_action` ด้วยบัญชีเจ้าหน้าที่ กติกาและ audit เดียวกับเว็บ ขั้นที่ย้อนกลับไม่ได้หรือฟอร์มยาวทำในเว็บ
- **การแจ้งเตือน:**
  - เด้งเฉพาะ P0 การยกระดับ เรื่องรอตัดสินเส้นทาง การส่งต่อ งานย่อย และการโต้แย้งหรือเปิดใหม่ของเขต
  - ส่งถึงผู้รับผิดชอบเรื่อง ถ้ายังไม่มีส่งถึงผู้กำกับงาน (ผอ.) ของกองนั้น
  - ข้อความที่รอส่งของคนเดียวกันรวมเป็นการเด้งครั้งเดียว
  - งบของเจ้าหน้าที่นับแยกจากของเขต: เรื่องปกติหยุดเมื่อใช้ไป 90% เรื่องด่วนหยุดเมื่อครบ 100%

**ผู้แจ้งภายใน:** เจ้าหน้าที่ที่เชื่อม LINE และยังไม่เป็นผู้แจ้ง กด "แจ้งปัญหา/ข้อเสนอแนะ" จากเมนูงานของกองได้ ระบบสร้างผู้แจ้งภายในในนามกองของตน ซึ่งส่งได้เฉพาะเรื่องแจ้งปัญหา/ข้อเสนอแนะ

## Considered Options

- **ให้ LLM ตัดสินอนุมัติลงทะเบียน:** ไม่เลือก กฎตรวจทะเบียนให้ผลแน่นอนและตรวจย้อนได้ LLM ถูกหลอกด้วยข้อความได้
- **เก็บค่ายืนยันแบบอ่านได้เพื่อแสดงผู้อนุมัติ:** ไม่เลือก เป็นข้อมูลส่วนบุคคลที่ไม่จำเป็นต้องเห็น
- **ให้ผู้แจ้งไม่ระบุตัวตนเป็นผู้แจ้งปกติที่รับรองอัตโนมัติ:** ไม่เลือก จะเบิกและคืนของได้
- **ส่งรายละเอียดเรื่องในข้อความเด้ง:** ไม่เลือก ข้อความเด้งขึ้นหน้าจอล็อกและอยู่ในประวัติแจ้งเตือนของเครื่อง
- **เด้งถึงทุกคนในกอง:** ไม่เลือก ผู้ใช้ไม่อยากให้รก

## Consequences

- ต้องมีทะเบียนพนักงานจริงก่อนเปิดการตรวจรหัสพนักงานใน production ตอนนี้มีแค่ชุดจำลอง 8 คน ถ้าเปลี่ยน `SECRET_KEY` ต้องนำเข้าทะเบียนใหม่ เพราะ hash ผูกกับ key
- ตำแหน่งและการแจ้งแบบไม่ระบุตัวตนเป็นข้อมูลส่วนบุคคลตาม PDPA ต้องมีประกาศความเป็นส่วนตัวและระยะเก็บที่องค์กรรับรองก่อนเปิดใน production
- แพ็กเกจฟรี 300 ข้อความ ถ้าให้เจ้าหน้าที่ 220 จะเหลือให้เขต 80 ข้อความ
- AI ยังทำแค่ดึงข้อมูลเป็น JSON ข้อความที่ผู้ใช้เห็นเป็นข้อความแม่แบบที่เขียนตามแนว /humanizer
