# ระดับฝ่ายเห็นทุกกอง และผู้ดูข้อมูลดูได้อย่างเดียว

เจ้าของระบบตัดสินวันที่ 31 ตุลาคม 2569 (grill หน้าเว็บ Q1 ถึง Q11) หลังพบว่า Supervisor ระดับฝ่ายเปิดคิวได้ทีละกอง ไม่มีหน้ารวมทุกกอง และไม่เห็นเรื่องปัญหาและข้อเสนอแนะที่แอดมินถืออยู่ ผู้บริหารบางคนต้องการแค่ดูงาน ไม่ต้องทำงานในระบบ ADR นี้ต่อจาก ADR 0031 (หน่วยงาน) และแก้บางส่วนของ ADR 0030 และของรายการปัญหาและข้อเสนอแนะวันที่ 14 ต.ค. 2569 ตามที่เขียนไว้ด้านล่าง

**ที่เลือก:**
- **ฝ่ายคือ ฝอจ. (Q2):** ฝ่ายหมายถึง ฝอจ. ทั้งฝ่าย ซึ่งในระบบมีฝ่ายเดียว ไม่ใช่ฝ่ายการไฟฟ้าเขต Supervisor ของฝ่ายคือบทบาท Supervisor ระดับฝ่ายที่มีอยู่แล้ว ตั้ง Supervisor ของกองและ Supervisor ระดับฝ่ายได้กี่คนก็ได้ (Q11)
- **หน้าทุกกอง (Q3):** Supervisor ระดับฝ่ายมีหน้าคิวทุกกองเหมือนแอดมิน และยังเลือกดูทีละกองได้ รายงานแบบทุกกองและ CSV ของหน้าทุกกองก็ใช้ได้
- **ปัญหาและข้อเสนอแนะ (Q4):** Supervisor ระดับฝ่ายเห็นแท็บนี้ทั้งหมด รวมเรื่องที่แอดมินถือ เปิดหน้าเรื่องได้ และส่งเรื่องที่แอดมินถือให้กองได้เหมือนแอดมิน ตรงกับหน้าที่ผู้ประสานระดับฝ่ายที่รับเรื่องซึ่งบอกไม่ได้ว่าเป็นของกองใด การตอบเรื่องที่แอดมินถือยังเป็นของแอดมิน
- **CSV ของปัญหาและข้อเสนอแนะ (Q10):** ส่งออกทุกแถวที่ตรงกับตัวกรองโดยไม่ตัดที่ 5,000 แถว และมีทุกอย่างที่หน้าเว็บแสดง คือข้อความที่แจ้งเต็ม ผู้แจ้ง และชื่อเจ้าหน้าที่ที่บันทึกแทน ผู้แจ้งที่ไม่ระบุตัวตนยังเป็นรหัสแทนตัวตาม ADR 0010 ไฟล์ไม่มี LINE ID หรือพิกัด และยังบันทึกทุกครั้งที่ดาวน์โหลด ข้อนี้แทนข้อตกลงวันที่ 14 ต.ค. 2569 (Q4, Q6, Q7) ที่ให้ CSV ไม่มีข้อมูลส่วนบุคคล
- **ผู้ดูข้อมูลสองระดับ (Q5, Q6):** ผู้ดูข้อมูลของกองผูกกับกองเดียว ผู้ดูข้อมูลระดับฝ่ายเห็นทุกกอง ทั้งสองบทบาทเห็นเท่ากับ Supervisor ของขอบเขตนั้น คือคิวทุกแท็บ หน้าเรื่อง ไฟล์แนบ งานสั่ง หน้าคลัง ตาราง ปฏิทิน รายงาน และ CSV ผู้ดูข้อมูลระดับฝ่ายเห็นหน้าทุกกองและแท็บปัญหาและข้อเสนอแนะด้วย
- **ดูได้อย่างเดียว (Q7):** ไม่มีปุ่มหรือฟอร์มให้กด หน้าเว็บขึ้นว่าบัญชีนี้ดูได้อย่างเดียว ถ้าส่งคำสั่งตรงมาที่ระบบจะถูกปฏิเสธ ไม่อยู่ในรายชื่อสมาชิก คนที่มอบงานได้ หรือผู้รับผิดชอบประจำงาน ไม่ได้อำนาจของกอง ไม่ได้รับแจ้งเตือน และ LINE ไม่มีเมนูเจ้าหน้าที่ให้
- **ใครตั้ง (Q8):** ตั้งได้เฉพาะแอดมิน ทั้งจากหน้าบัญชีเจ้าหน้าที่และหน้าผู้ใช้ LINE OA ต้องใส่เหตุผล และมีประวัติเหมือนบทบาทอื่น บทบาทรวมกันได้ เช่น ผู้ดูข้อมูลระดับฝ่ายที่เป็นสมาชิกกองหนึ่งด้วย จะทำงานได้ในกองของตัวเอง และดูกองอื่นได้อย่างเดียว
- **บัญชีเดิมที่ถูกระงับ (Q1, Q9):** สถานะปัจจุบันเป็นตัวตัดสิน ถ้าผู้ใช้ LINE OA ที่ยืนยันตัวตนแล้วยังใช้งานได้ บัญชีเจ้าหน้าที่เดิมของพนักงานคนนั้นที่ถูกระงับค้างไว้ (เช่น ก่อนล้างข้อมูล LINE วันที่ 29 ต.ค.) จะเปิดใช้อีกครั้ง สิทธิ์เก่าถอนออกทั้งหมด และได้แค่สิทธิ์ตามทะเบียนกับสิทธิ์ที่แอดมินตั้งตอนนี้ ประวัติเดิมยังเก็บไว้

- **แท็บนี้มีแค่เรื่องจากปุ่ม (Q12, Q13 ส่วนเพิ่มวันเดียวกัน):** แท็บปัญหาและข้อเสนอแนะและ CSV ของแท็บแสดงเฉพาะเรื่องที่มาจากปุ่ม ปัญหา/ข้อเสนอแนะ ใน rich menu ระบบดูจากชื่อเมนูของเรื่องที่ขึ้นต้นด้วยชื่อปุ่ม ทั้งชื่อปัจจุบันและชื่อที่ปุ่มเคยใช้ เรื่องที่เจ้าหน้าที่แจ้งผ่านปุ่มแจ้งปัญหาในเมนูเจ้าหน้าที่ใช้หน้าเลือกกองแบบเดียวกัน จึงนับรวมด้วย เรื่องประเภทแจ้งปัญหาจากปุ่มอื่น เช่น ติดตามสถานะการซ่อม และเรื่องที่เจ้าหน้าที่บันทึกแทนทางโทรศัพท์ อยู่ในคิวของกองเท่านั้น
- **Log การใช้งาน (Q14 ถึง Q17):** หน้าใหม่ในกลุ่มคนและสิทธิ์ แสดงการเข้าสู่ระบบ การออกจากระบบ การเข้าสู่ระบบไม่สำเร็จ และกิจกรรมอื่นที่ระบบบันทึกของบัญชีเจ้าหน้าที่ ใหม่สุดขึ้นก่อน เวลาเป็นเวลาไทย กรองตามบัญชี ชนิดกิจกรรม และช่วงวันที่ได้ ตอนเข้าสู่ระบบระบบเก็บ IP address และเบราว์เซอร์ ถ้าเข้าไม่สำเร็จเก็บแค่ชื่อผู้ใช้ที่พิมพ์มา ไม่เก็บรหัสผ่าน ชื่อกิจกรรมเป็นภาษาไทยทุกแถว ชนิดที่ยังไม่มีชื่อเฉพาะใช้ชื่อหมวด เปิดได้เฉพาะแอดมิน ดาวน์โหลด CSV ได้ตามตัวกรอง และระบบบันทึกทุกครั้งที่มีคนดาวน์โหลด

**ผลที่ตามมา:**
- ระบบแยกสิทธิ์อ่านออกจากสิทธิ์ทำงาน ทุกเส้นทางที่บันทึกหรือเปลี่ยนข้อมูลยังถามสิทธิ์ทำงานแบบเดิม ผู้ดูข้อมูลจึงได้แค่สิทธิ์อ่านเพิ่มขึ้นมา ถ้ามีหน้าใหม่ที่ควรให้ผู้ดูข้อมูลเปิดได้ ต้องเปิดสิทธิ์อ่านของหน้านั้นเอง
- ผู้ใช้ LINE OA ที่แอดมินตั้งเป็นผู้ดูข้อมูลยังได้สมาชิกกองตามทะเบียนพนักงานเหมือนเดิม ถ้าต้องการให้ดูได้อย่างเดียวจริง แอดมินต้องถอนสิทธิ์สมาชิกกองที่ได้ตามทะเบียนออก
- หน้าข้อมูลประกอบงาน (คำที่ระบบจำ ปิดข้อมูลก่อนส่ง AI หน้าที่ของกอง เอกสารความรู้) และหน้าตั้งค่ายังเป็นของแอดมินและเจ้าหน้าที่เหมือนเดิม
- ไฟล์ CSV ของปัญหาและข้อเสนอแนะมีชื่อและข้อความของผู้แจ้งแล้ว คนที่ดาวน์โหลดต้องเก็บไฟล์ให้ปลอดภัย
- Log การเข้าสู่ระบบเริ่มมีตั้งแต่วันที่ deploy งานนี้ ก่อนหน้านั้นระบบไม่ได้บันทึกไว้ ถ้ามีชนิดกิจกรรมใหม่ ควรเพิ่มชื่อภาษาไทยให้ด้วย ไม่อย่างนั้นจะขึ้นเป็นชื่อหมวด
- ถ้าเปลี่ยนชื่อปุ่ม ปัญหา/ข้อเสนอแนะ เรื่องเก่ายังอยู่ในแท็บ เพราะระบบจำชื่อที่ปุ่มเคยใช้จากเมนูและ flow ที่มีอยู่
