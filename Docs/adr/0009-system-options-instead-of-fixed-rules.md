# ตัวเลือกระบบแทนกฎที่ฝังในโปรแกรม เริ่มจากการแยกหน้าที่และผู้อนุมัติการลงทะเบียน

ผู้ใช้กำหนดวันที่ 10 ตุลาคม 2569 ว่าตอนนี้ให้แต่ละกองมีผู้ใช้คนเดียวที่ทำได้ทุกงานของกอง และให้ออกแบบระบบให้ยืดหยุ่น เพราะ flow และกฎเกณฑ์จะเปลี่ยนภายหลัง งานอย่างการลงทะเบียนต้องมีตัวเลือกเสมอ ไม่ fix แต่ต้องสะดวกและปลอดภัยต่อระบบ

จึงเพิ่ม**ตัวเลือกระบบ** (`operations/options.py`, หน้าแอดมิน "ตัวเลือกระบบ") ตัวเลือกแต่ละข้อมีค่าให้เลือกจำกัด และค่าแรกคือค่าที่ปลอดภัยที่สุดซึ่งใช้เมื่อยังไม่มีใครเลือก เฉพาะแอดมินเปลี่ยนได้ ต้องมีเหตุผล และทุกการเปลี่ยนอยู่ใน audit trail ตัวเลือกแรก ๆ:

- **การแยกหน้าที่ในเรื่องเดียวกัน:** เปิด (ค่าเริ่มต้น เหมือนเดิม) หรือปิด เมื่อปิด คนเดียวทำขั้นที่ต่อกันได้ เช่น อนุมัติแล้วจ่ายเอง หรือบันทึกผลแก้ปัญหาแล้วบันทึกคำตอบแทนเขตเอง ทุกขั้นยังบันทึกชื่อผู้ทำ
- **ผู้อนุมัติการลงทะเบียนผู้แจ้งทาง LINE:** แอดมินเท่านั้น (ค่าเริ่มต้น), แอดมินหรือผู้กำกับงานในกองใดก็ได้ หรือแอดมินหรือเจ้าหน้าที่กองใดก็ได้ ไม่มีตัวเลือกอนุมัติอัตโนมัติ

และเพิ่มปุ่ม**ทำได้ทุกงานในกอง** ในหน้าบัญชีของแอดมิน ซึ่งให้ทุกบทบาทของกองและอำนาจที่กองมีต่องานของตัวเอง (อนุมัติเบิก จัดสรร รับรองสภาพ ข้อยกเว้นระดับ หรือการตัดสินเส้นทางสำหรับผู้ประสานระดับฝ่าย) ในครั้งเดียว แต่บันทึกเป็นรายการแยก จึงถอนทีละรายการได้เมื่อจะแยกหน้าที่ภายหลัง

ข้อนี้เปลี่ยนการแยกหน้าที่ที่ฝังในโค้ด (M07 Q4, M08 Q5, รอบโครงสร้างจริง Q9) ให้เป็นตัวเลือก ส่วนผู้ช่วยเหลือระบบยังไม่ถูกจำกัดไม่ว่าเลือกแบบใด (ADR 0007)

## Considered Options

- **ใส่การแยกหน้าที่ในเอกสารกติกา (policy) ที่ต้องมีผู้รับรองและเลขอนุมัติ:** ไม่เลือก ผู้ใช้ต้องการเปลี่ยนได้สะดวก หน้าแอดมินที่บังคับเหตุผลและบันทึกประวัติให้ทั้งความสะดวกและการตรวจย้อนหลัง
- **ปิดการแยกหน้าที่ในโค้ดสำหรับโครงสร้างจริง:** ไม่เลือก กลับมาเปิดภายหลังต้องแก้โปรแกรม
- **อนุมัติการลงทะเบียนอัตโนมัติ:** ไม่เลือกตอนนี้ เพราะใครก็อ้างเขตได้ ถ้าต้องการภายหลังควรมีรายชื่อที่แอดมินนำเข้าก่อน
- **ตารางตั้งค่าแบบข้อความอิสระ (key/value ใด ๆ):** ไม่เลือก ค่าผิดอาจทำให้ระบบทำงานแบบที่ไม่ได้ออกแบบไว้ ตัวเลือกจึงจำกัดค่าและตรวจในโค้ด

## Consequences

- ตัวเลือกใหม่ = หนึ่งรายการใน `OPTIONS` (ค่าที่ปลอดภัยเป็นค่าแรก) กับจุดที่อ่านค่า ไม่ต้องเพิ่ม migration
- เมื่อปิดการแยกหน้าที่ การกันไว้ก่อนหายไป เหลือการตรวจย้อนหลังจากไทม์ไลน์และ audit ผู้ตรวจสอบภายในควรรับรองก่อนใช้ใน production
- ผู้ที่ได้สิทธิ์อนุมัติการลงทะเบียนแต่ไม่ใช่แอดมินเห็นเฉพาะหน้ารับรองผู้แจ้ง การสร้างผู้แจ้งโดยตรงยังเป็นของแอดมิน
- เทสต์และกติกาจำลองใช้ค่าเริ่มต้น (แยกหน้าที่) เว็บบนเครื่องปิดการแยกหน้าที่และใช้บัญชีเดียวต่อกอง
