# ระบบนี้ไม่ถือยอดของ: คลังจำลองแทนระบบเดิม และจัดสรรเฉพาะเมื่อของแย่งกัน

ผู้ใช้ยืนยันวันที่ 7 ตุลาคม 2569 (M07 Q1, Q8–Q10, Q20) ว่าระบบรับเรื่องไม่เก็บยอดของทางการและไม่กันของไว้ให้เรื่องใด ทางเชื่อมคลังมีสองโหมด: **คลังจำลอง** (นอก production) ทำหน้าที่แทนระบบทะเบียนเดิม หักยอดและเลขเครื่องจำลองภายใต้ lock และออกเลขเอกสารจ่ายจำลอง เพื่อให้ทดสอบได้จริงว่าจ่ายพร้อมกันไม่เกินยอด; **อ้างเลขเอกสาร** (`manual_reference`, ใช้จริง) เจ้าหน้าที่จ่ายในระบบเดิมก่อนแล้วกรอกเลขเอกสาร ระบบนี้ไม่หักยอด ยอดที่นำเข้าพร้อม as_of เป็นข้อมูลประกอบและไม่บล็อกการบันทึกสิ่งที่เกิดขึ้นแล้ว ส่วนจำนวนอนุมัติค้างและจำนวนจัดสรรบล็อกเสมอ

การอนุมัติไม่ใช่สัญญาว่าจะจ่ายครบและไม่กันของ เมื่อส่วนค้างรวมของรายการหนึ่งในทุกเรื่องที่เปิดอยู่มากกว่ายอดพร้อมจ่าย การจ่ายรายการนั้นต้องมี**การจัดสรร**จากผู้ถืออำนาจ "จัดสรรของขาด" ระบุจำนวนต่อเรื่องรวมไม่เกินยอดพร้อมจ่าย เพื่อให้ผู้มีอำนาจเลือกผู้ได้ของ (R08) ไม่ใช่ผู้ที่บันทึกจ่ายก่อน การจัดสรรมีผลเฉพาะขณะของแย่งกัน และเป็นโมฆะทั้งหมดเมื่อยอดลดต่ำกว่าที่จัดสรรไว้

## Considered Options

- **ระบบนี้เก็บยอดเองและหักทุกครั้งที่จ่าย:** ไม่เลือก เพราะจะมียอดทางการสองชุดที่ต้องกระทบกันตลอด ขัดกับหลักว่าระบบเดิมเป็นเจ้าของยอด
- **กันของตอนอนุมัติ:** ไม่เลือก เพราะทำให้การอนุมัติกลายเป็นคำสัญญาว่าจะได้ของ และซ้ำกับการกันของในระบบเดิม
- **ใครจ่ายก่อนได้ก่อน:** ไม่เลือก เพราะผู้ได้ของถูกตัดสินโดยลำดับการบันทึก ไม่ใช่ผู้มีอำนาจ

## Consequences

- ในโหมดอ้างเลขเอกสาร ถ้ายอดเก่าหรือไม่มียอด ระบบไม่รู้ว่าของแย่งกันหรือไม่ จึงไม่บังคับการจัดสรร และข้อเท็จจริง "ของไม่พอ" เป็น "ไม่ทราบ" จนกว่าจะนำเข้ายอดใหม่
- การยกเลิกหรือแก้รายการจ่ายไม่คืนยอดเองในทั้งสองโหมด การปรับคลังจำลองเป็นงานแอดมินแยกพร้อมเหตุผล เหมือนเอกสารแก้ของระบบเดิม
- เมื่อเชื่อม API ระบบเดิม (M11) โหมดใหม่ต้องรักษาสัญญาเดียวกัน: ระบบนี้อ้างผลธุรกรรมของระบบเดิม ไม่ใช่สร้างยอดเอง
- การรับของคืน (M08, 7 ตุลาคม 2569) ใช้สัญญาเดียวกัน: ของที่มาถึงอยู่ใน "รอตรวจ" ไม่เพิ่มยอดพร้อมจ่าย จนผลตรวจสภาพ "พร้อมใช้" ที่มีผู้มีอำนาจรับรองสภาพย้ายไปพร้อมจ่าย; ในโหมดอ้างเลขเอกสาร การรับและผลตรวจอ้างเลขเอกสารของระบบเดิมโดยไม่เปลี่ยนตัวเลขในระบบนี้
