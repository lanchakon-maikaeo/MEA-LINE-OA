# งานใน LINE ของ Supervisor สองระดับและประกาศผ่าน Mini App

เจ้าของระบบกำหนดวันที่ 31 ตุลาคม 2569 ให้เมนูรอบที่ 7 แยกการทำงานตาม Supervisor ระดับฝ่ายและระดับกอง/ศูนย์ และให้ทั้งสองระดับสร้าง Broadcast ผ่าน LINE Mini App โดยอ้างอิงหน้าสร้าง Broadcast ของ LINE Official Account Manager ข้อสรุป Q1 ถึง Q14 และแบบหน้าจอได้รับการยืนยันแล้ว เจ้าของอนุญาตให้เริ่มพัฒนา การเปิดใช้งานจริงต้องตรวจสอบแยกจากการยอมรับแบบ

## ข้อกำหนดจากเจ้าของระบบ

- Supervisor ระดับฝ่ายกด งานสั่งที่ได้รับ แล้วเห็นงานที่เข้ามาทุกกอง รวมข้อเสนอแนะ เปิดรายละเอียด รับเรื่อง และเลือกกองเพื่อส่งต่อให้ Supervisor กองได้
- Supervisor ระดับกอง/ศูนย์กดปุ่มเดียวกันแล้วเห็นงานทั้งหมดในหน่วยตน รวมข้อเสนอแนะ เปิดรายละเอียดและรับเรื่องได้
- รายการและรายละเอียดแสดงเป็นการ์ดในแชต LINE พร้อมปุ่มดำเนินการ
- Supervisor ทั้งสองระดับสร้าง Broadcast และตั้งค่าผ่าน LINE Mini App ได้ โดยใช้ LINE Official Account Manager เป็นตัวอ้างอิง
- ใช้แบบรอบที่ 7 ใน commit b655a91 เป็นฐานหน้าตา; คงปุ่มบริการตามภาพที่เจ้าของยืนยัน

## ความต่างจากโค้ดที่ตรวจ

ฐานโค้ดที่อ่านคือ f817870 ปุ่ม งานสั่งที่ได้รับ เปิดเฉพาะคำสั่งงานของ Supervisor ส่วนเรื่องจากผู้แจ้งเป็นข้อมูลอีกประเภทหนึ่ง การรับเรื่องเข้าดำเนินการ การรับเป็นผู้รับผิดชอบ และการตอบรับส่งต่อเป็นคนละคำสั่ง Supervisor ระดับฝ่ายมีสิทธิ์กำกับทุกกอง แต่ไม่ได้อำนาจรับเรื่องของทุกกองโดยอัตโนมัติ ตาม ADR 0016 และ 0039

ข้อสรุป Q4 อนุญาต Broadcast จาก Supervisor ทั้งสองระดับ แทนข้อห้ามส่งกระจายเดิมใน PROJECT.md สำหรับการประกาศผ่านหน้าที่กำลังออกแบบนี้ งบข้อความและการจัดการส่งไม่สำเร็จยังต้องตัดสิน

## ข้อสรุป Q1 ถึง Q5

- Q1: ฝ่ายรับเรื่องเข้าดำเนินการแทนกองได้ บันทึกผู้กดรับ กองไม่ต้องรับซ้ำ งานที่เข้ากองโดยตรงกองรับเองได้โดยไม่ต้องรอฝ่าย เพิ่มอำนาจรับเรื่องให้ฝ่ายจาก ADR 0016
- Q2: เมื่อฝ่ายเลือกกองและยืนยันส่งต่อ เปลี่ยนเจ้าภาพทันที ไม่รอปลายทางตอบรับ ข้อนี้ใช้กับการส่งต่อโดยฝ่าย ไม่ได้ตัดสินเปลี่ยนการขอส่งต่อระหว่างกองทั่วไป
- Q3: รายการรวมเรื่องและคำสั่งงานใน DED Center รวมปัญหา/ข้อเสนอแนะตามสิทธิ์ ไม่รวมรายการจาก Google Form หรือชีทที่ไม่มีเรื่องในระบบ
- Q4: Supervisor ฝ่ายและกองมีขอบเขตผู้รับ Broadcast เท่ากัน เลือกส่งถึงผู้ติดตาม OA ทั้งหมดหรือกลุ่มที่ตั้งค่าได้ตามรูปแบบ LINE OA Manager ผ่านหน้า Mini App ไม่มีข้อจำกัดให้กองส่งเฉพาะหน่วยตนตามคำแนะนำก่อนหน้า
- Q5: Supervisor กองสร้าง ดูตัวอย่าง และยืนยันส่งได้เอง ไม่รอฝ่ายอนุมัติ หน้าสรุปแสดงข้อความ กลุ่มผู้รับ จำนวนและเวลาส่ง พร้อมประวัติผู้ส่ง

## ข้อสรุป Q6 ถึง Q10

- Q6: การรับเรื่องกับการมอบหมายผู้รับผิดชอบแยกกัน ผู้กดรับมีชื่อในประวัติ แต่ไม่กลายเป็นผู้รับผิดชอบอัตโนมัติ ใช้ผู้รับผิดชอบประจำงานของหน่วย และ Supervisor เปลี่ยนผ่านปุ่ม มอบหมาย ได้
- Q7: ฝ่ายส่งข้ามกองแล้วล้างการมอบหมายเดิม ใช้ผู้รับผิดชอบตามงานของปลายทาง ถ้าไม่มีคนให้ขึ้น รอมอบหมาย ในคิว Supervisor ปลายทาง ประวัติงานเดิมคงอยู่
- Q8: เปิดรายการที่ งานรอรับเรื่อง ก่อน มีตัวกรอง กำลังดำเนินการ / รอมอบหมาย / ทั้งหมด ฝ่ายกรองกองได้ ส่วน Supervisor กองเห็นเฉพาะหน่วยตน การ์ดแสดงเลขเรื่อง หัวข้อ กอง สถานะ ผู้รับผิดชอบ วันกำหนด และปุ่ม ดูรายละเอียด ปุ่มรับเรื่องกับส่งต่ออยู่ในรายละเอียด
- Q9: เจ้าของร่างและ Supervisor ฝ่ายแก้หรือยกเลิก Broadcast ที่ตั้งเวลาไว้ได้ Supervisor คนอื่นดูประวัติได้แต่แก้ไม่ได้ สิทธิ์นี้ยังไม่ได้ขยายให้สมาชิกทั่วไปดูประวัติประกาศ
- Q10: เมื่อโควตาไม่พอส่งครบกลุ่ม ให้หยุดรายการและแจ้งผู้สร้างเพื่อลดกลุ่มหรือจัดการโควตาก่อน ไม่เลือกส่งบางคนเพราะโควตาเหลือไม่พอ ข้อนี้ยังไม่ตัดสินการกู้คืนกรณีเครือข่ายผิดพลาดหลังเริ่มส่งแล้ว

## ข้อสรุป Q11 ถึง Q14 และแบบหน้าจอ

- Q11: รุ่นแรกมีข้อความ รูปภาพ วิดีโอ ภาพกดลิงก์ และการ์ดพร้อมปุ่ม เก็บร่าง ดูตัวอย่าง ส่งทดสอบถึงตนเอง ส่งทันที ตั้งเวลา และดูประวัติ คูปองกับแบบสอบถามเพิ่มเมื่อมีงานที่ต้องใช้
- Q12: ใช้สมาชิกกลุ่ม ณ เวลาส่งจริง จำนวนตอนตั้งเวลาเป็นประมาณการ ต้องตรวจโควตาอีกครั้งก่อนส่ง
- Q13: รายการเดิมรอส่งจนผู้ใช้กดเริ่มแก้ไข จากนั้นพักการส่งจนตรวจสรุปและยืนยันตั้งเวลาใหม่ ปิดหน้าค้างไว้ไม่ทำให้ส่งต่อเอง
- Q14: ระบบลองส่งต่อเฉพาะส่วนที่ยังไม่สำเร็จโดยป้องกันส่งซ้ำ หากกู้ไม่ได้แสดง ส่งไม่ครบ พร้อมผลที่ยืนยันได้และแจ้งผู้สร้าง ส่วนที่ยังไม่ทราบผลต้องตรวจสอบก่อนลองส่งซ้ำ
- เจ้าของให้เริ่มออกแบบหน้าจอ Mini App ที่ใช้ง่าย เลือก เพื่อนทั้งหมด หรือ Segment และสร้าง Segment เองได้

แบบจำลองในแชตใช้สี่ขั้น: ผู้รับ / ข้อความ / เวลาส่ง / ตรวจสอบ พร้อมตัวเลือกทุกคนหรือกลุ่มและหน้าสร้างกลุ่ม ตัวกรองเขตกับประเภทผู้ใช้ในแบบจำลองเป็นตัวอย่างการออกแบบ ยังไม่ถือเป็นขอบเขตสุดท้ายของตัวสร้าง Segment จำนวนผู้รับและโควตาเป็นข้อมูลจำลอง และไม่มีการส่งข้อความจริง

ยังต้องตรวจความสามารถ audience ของบัญชีอ้างอิงและกำหนดเงื่อนไข Segment ที่ต้องใช้จริง รวมถึงสิทธิ์แก้กลุ่ม รูปแบบรวมเงื่อนไข และผลต่อประกาศที่ตั้งเวลาไว้

## ผู้ส่งได้รับประกาศและการใช้ร่วมกับเว็บ

เจ้าของยืนยันหลังดูแบบ Mini App ให้ Supervisor เป็นทั้งผู้ส่งและผู้รับประกาศของตัวเอง และให้สอดคล้องกับหน้าเว็บ

- ผู้สร้างประกาศได้รับข้อความประกาศเดียวกันจาก OA ในแชตของตนเมื่อส่งจริง แม้ไม่อยู่ใน Segment ที่เลือก ถ้าอยู่ในกลุ่มหรือส่งถึงเพื่อนทั้งหมดแล้ว ให้ได้รับเพียงครั้งเดียว
- จำนวนผู้รับที่ใช้ตรวจโควตารวมผู้สร้างประกาศด้วยโดยไม่ซ้ำ กฎรับสำเนานี้แยกจากปุ่มส่งทดสอบถึงตนเอง
- Mini App กับหน้าเว็บใช้ประกาศ ร่าง กลุ่มผู้รับ เวลาส่ง ผลการส่ง และประวัติชุดเดียวกัน แก้ไขจากช่องทางใด อีกช่องทางต้องเห็นข้อมูลล่าสุด
- ใช้สิทธิ์เดียวกันทั้งสองช่องทาง: Supervisor ทั้งสองระดับเลือกผู้รับได้เท่ากัน เจ้าของร่างกับ Supervisor ฝ่ายแก้หรือยกเลิกได้ตาม Q9 และใช้กฎพักการส่งเมื่อเริ่มแก้ตาม Q13
- การยืนยันส่งจากสองหน้าต้องเป็นการส่งรายการเดียวกัน ไม่สร้างงานส่งซ้ำ และยังตรวจสิทธิ์กับข้อมูลล่าสุดก่อนส่ง
- กรณีฝ่ายแก้ร่างแทนผู้สร้าง ยังต้องกำหนดในรอบถัดไปว่าต้องส่งสำเนาถึงผู้ยืนยันคนใหม่เพิ่มด้วยหรือไม่ กรณีผู้สร้างบล็อก OA หรือรับข้อความไม่ได้ ต้องแสดงผลจริง ไม่ถือว่าส่งถึงแล้ว

แบบจำลองปรับยอดผู้รับรวมผู้ส่งและเพิ่มบรรทัดสำเนาถึงผู้ส่งแล้ว ส่วนโปรแกรมจริงของเว็บ Mini App และการส่ง LINE ยังไม่ได้พัฒนาในรอบออกแบบนี้

## ข้อมูล LINE ที่ตรวจแล้ว

แนวทางที่เป็นไปได้คือเปิดหน้าสร้างประกาศใน Mini App แล้วให้ระบบ DED ตรวจสิทธิ์และส่งออกผ่าน OA Messaging API เป็นข้อเสนอทางเทคนิคจากความสามารถของแพลตฟอร์ม ไม่ใช่ความสามารถสำเร็จรูปที่คัดลอก OA Manager มาได้ทุกอย่าง

- [LINE MINI App](https://developers.line.biz/en/docs/line-mini-app/develop/web-to-mini-app/) เป็นเว็บที่ใช้ LIFF และต้องมีเว็บเซิร์ฟเวอร์
- [Messaging API](https://developers.line.biz/en/docs/messaging-api/sending-messages/) แยกการส่งถึงผู้ติดตามทุกคนกับการเลือกผู้รับ จึงต้องกำหนดกลุ่มผู้รับของ DED ให้ชัดก่อนเลือกวิธีส่ง
- [การใช้ audience](https://developers.line.biz/en/docs/messaging-api/using-audience/) ใช้ร่วมระหว่าง Manager กับ API สำหรับ OA เดียวกันได้ แต่ API สร้าง audience ได้ไม่ครบทุกชนิดที่ Manager สร้างได้
- [Service messages ของ Mini App](https://developers.line.biz/en/docs/line-mini-app/develop/service-messages) มีเงื่อนไขผูกกับการกระทำของผู้ใช้ จึงไม่ใช้แทนระบบส่งประกาศทั่วไป

ลิงก์อ้างอิงที่เจ้าของส่งคือ [หน้าสร้าง Broadcast](https://manager.line.biz/account/@705ttrga/broadcast/create) และ [ช่องทาง 2012304618](https://developers.line.biz/console/channel/2012304618/basics) ทั้งสองเปิดไปหน้าเข้าสู่ระบบในการตรวจครั้งนี้ ยังไม่ยืนยันประเภทช่องทาง provider การเชื่อม OA หรือสถานะ Mini App และยังไม่ได้สรุปว่า OA ในลิงก์ต้องแทน OA ที่โปรเจกต์ใช้อยู่

## ข้อยืนยันก่อนพัฒนา

- ปุ่มสั่งงานอยู่ภายในเมนูเพิ่มเติม และเมนูเพิ่มเติมมีเฉพาะสั่งงาน ส่วนรายการอื่นทำภายหลัง
- เฉพาะ Supervisor ระดับฝ่ายสร้างคำสั่งงานได้ ทั้งจาก LINE และหน้าเว็บ Supervisor ระดับกอง/ศูนย์ยังรับเรื่องและมอบหมายผู้รับผิดชอบของงานที่มีอยู่ตามสิทธิ์เดิมได้
- ต้องตรวจสิทธิ์ซ้ำเมื่อยืนยันสร้างงาน ปุ่มเก่า ร่างค้าง และการพิมพ์คำสั่งตรงไม่ให้สิทธิ์เพิ่ม
- Supervisor ทั้งสองระดับยังใช้ Broadcast ได้ตามข้อสรุปเดิม
- Mini App ใช้สีเขียวกับสีขาว และภาษาสุภาพทางการ

## สถานะการพัฒนา

ปรับสิทธิ์สร้างคำสั่งงานให้เฉพาะ Supervisor ฝ่ายแล้ว ทั้งหน้าเว็บ แชต และจุดสร้างงานร่วม เมนูเพิ่มเติมมีปุ่มสั่งงานเฉพาะผู้มีสิทธิ์ และแท็บหลักไม่แสดงแท็บสั่งงาน บัญชี Supervisor กองยังจัดการงานที่มีอยู่ได้ตามสิทธิ์เดิม

ส่วนคิวงานรวม การรับเรื่องแทนกอง การส่งต่อจากรายละเอียด และ Mini App/Broadcast ตามข้อสรุปข้างต้นยังไม่ถือว่าพัฒนาเสร็จหรือเปิดใช้งาน ต้องตรวจจากการเปลี่ยนแปลงและผลทดสอบของแต่ละส่วน
