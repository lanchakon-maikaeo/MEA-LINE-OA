# รุ่นการตั้งค่า AI รุ่นเดียวใช้กับทุกงาน และผู้ให้บริการ AI จัดการในเว็บ

เจ้าของระบบอยากเลือกผู้ให้บริการ AI ได้เอง ทั้ง Typhoon, Gemini และรายอื่น กรอกคีย์เองอย่างปลอดภัย และให้หน้าตั้งค่า AI ใช้ง่ายโดยไม่ต้องอ่านคำอธิบาย (grill 31 ต.ค. 2569 Q1 ถึง Q25) เดิมแต่ละงานของ AI มีรุ่นและเกณฑ์ของตัวเอง และเลขรุ่นของ Mac กับ production ไม่ตรงกัน ADR นี้แทนข้อ "รุ่นแยกตามงาน" ของ ADR 0001 และส่วนที่ว่าเครื่องนี้ออกเลขรุ่นเองของ ADR 0020 ส่วนอื่นของทั้งสอง ADR ยังใช้

**ที่เลือก:**
- **รุ่นเดียวทุกงาน (Q9, Q13):** รุ่นการตั้งค่า AI หนึ่งรุ่นมีลำดับโมเดลเดียวที่ทุกงานใช้ร่วมกัน ได้แก่ สกัดร่าง คัดกรอง ตอบแชต เสนอกอง ยกคำสำคัญ เรียบเรียงสถานะจากชีท agent ใน LINE และตอบอิสระ
- **เกณฑ์เดียว (Q13, Q14):** การประเมินรันการตรวจของทุกงาน รวมงานที่ปิด AI อยู่ และรุ่นผ่านเมื่อทุกงานผ่าน สวิตช์เปิดปิด AI ทีละงานยังอยู่ เมื่อเปิดใช้รุ่นใหม่ งานที่ปิดอยู่ยังปิด
- **งานที่ยังไม่มีข้อมูลให้ประเมิน (31 ต.ค. 2569):** เช่น เสนอกองเมื่อหน้าที่ของกองยังว่าง หรือคัดกรองเมื่อยังไม่มีกติกาที่ใช้อยู่ งานนั้นได้สถานะ "ยังไม่พร้อมประเมิน" และไม่กันทั้งรุ่น แต่ต้องปิด AI ไว้ จะเปิดได้เมื่อมีข้อมูลแล้วประเมินรุ่นนั้นใหม่จนผ่าน งานที่ประเมินได้แต่ไม่ผ่านยังกันทั้งรุ่น
- **ค่าเฉพาะงาน (Q15):** รูปแบบ harness จำนวนตัวอย่าง และการอ่านเลข SAP เมนู กับข้อเท็จจริงของ DED Center อยู่ในรุ่นเดียวกัน ตั้งต้นจากรุ่นสกัดร่างที่ใช้อยู่ งานอื่นเรียกครั้งเดียวเหมือนเดิม
- **ของเดิม (Q16):** รุ่นแยกตามงานทำงานต่อจนรุ่นรวมรุ่นแรกเปิดใช้ แล้วเลิกใช้พร้อมกัน ประวัติยังดูได้
- **เลขรุ่น (Q17, Q18, Q21):** แบบ CalVer คือวันที่ตาม ISO 8601 (ค.ศ.) กับลำดับของวันนั้น เช่น 2026.10.31.1 ออกเลขบนเครื่องที่ประเมินเท่านั้น production นำเข้าแล้วใช้เลขเดียวกัน เลข v ของรุ่นเก่าคงเดิม
- **บน production (Q17, Q19, Q22):** สร้างรุ่นไม่ได้ นำเข้าไฟล์ผลประเมินที่เซ็นบน Mac ด้วยคำสั่งเดิม ถ้ายังไม่มีผู้ให้บริการที่ที่อยู่ API ตรงกัน ระบบไม่นำเข้าและบอกชื่อที่ต้องเพิ่ม คีย์ไม่ติดไปกับไฟล์ ต้องทดสอบการเชื่อมต่อด้วยคีย์ของเครื่องนั้นก่อนเปิดใช้
- **ข้อมูลไม่ตรง (31 ต.ค. 2569):** เกณฑ์ของคัดกรอง ตอบแชต และเสนอกองผูกกับกติกา คลังคำตอบ และหน้าที่ของกองในเครื่อง ส่วนงานสกัดร่างที่ใช้ตัวอย่างผูกกับตัวอย่างที่ค้นมา ถ้าข้อมูลบน production ต่างจากตอนประเมิน ระบบไม่นำเข้าและบอกว่าข้อมูลส่วนใดต่าง
- **ปุ่มเดียว (Q25):** บน Mac ปุ่ม "สร้างและประเมิน" สร้างรุ่น ทดสอบการเชื่อมต่อ และประเมินทุกงานเบื้องหลัง จากนั้นจึงกดเปิดใช้
- **โควตาหมด (Q20):** ถ้าผู้ให้บริการตอบ HTTP 429 ระหว่างประเมินงานใด ผลของงานนั้นไม่ถูกบันทึก งานนั้นรอโควตาแล้วประเมินใหม่ ส่วนงานที่ประเมินเสร็จแล้วเก็บผลไว้ ระบบไม่บันทึกผลที่ปนคำตอบของโมเดลสำรอง
- **ผู้ให้บริการในเว็บ (Q3, Q23):** แอดมินผู้พัฒนาเพิ่มผู้ให้บริการได้พร้อมเหตุผลและประวัติ ต้องเป็น HTTPS พอร์ต 443 ห้าม redirect ชื่อโดเมนต้องชี้ที่อยู่สาธารณะเท่านั้น และเป็น API แบบ OpenAI โดเมนที่อนุญาตคือโดเมนของผู้ให้บริการที่บันทึกไว้ แทน AI_ALLOWED_HOSTS ส่วน "บังคับรูปแบบคำตอบ" เป็นค่าของผู้ให้บริการแต่ละราย แทน AI_SCHEMA_ENFORCED_HOSTS
- **คีย์ (Q4):** เข้ารหัสด้วยกุญแจที่อยู่นอกฐานข้อมูลเหมือนเดิม ต้องกรอกรหัสผ่านของตัวเองก่อนบันทึก เปลี่ยน หรือลบคีย์ ระบบลองเรียกผู้ให้บริการทันทีหลังบันทึก ลบคีย์ได้เมื่อไม่มีรุ่นที่ใช้งานอยู่อ้างถึง
- **โมเดลเป็นข้อมูล (Q5, Q6, Q24):** รายชื่อโมเดลแก้ได้ในเว็บ ระบบใส่ Gemini 3.8 Flash, 3.5 Flash-Lite, 3.1 Flash-Lite และ Typhoon ไว้ตามลำดับนี้ โมเดลที่เคยอยู่ในรุ่นใดซ่อนได้แต่ลบไม่ได้
- **ข้อมูลส่วนบุคคล (Q10):** ทุกผู้ให้บริการได้รับข้อความที่ปิดข้อมูลแล้วตาม ADR 0014 ไม่มีที่ปิดการทำงานนี้

**ผลที่ตามมา:**
- ถ้างานหนึ่งไม่ผ่าน ทั้งรุ่นเปิดใช้ไม่ได้ แม้งานนั้นปิด AI อยู่
- การเพิ่มโดเมนใหม่ไม่ต้องแก้เครื่องหรือ deploy แต่แอดมินผู้พัฒนาจึงส่งข้อความที่ปิดข้อมูลแล้วไปยังโดเมนใหม่ได้ ซึ่งมีประวัติบันทึกไว้
- แผนฟรีของ Gemini นำข้อความไปใช้ปรับปรุงบริการ ใช้ได้กับข้อมูลจำลองจนกว่าองค์กรอนุมัติหรือเปลี่ยนเป็นแผนเสียเงิน
