# กระทบยอดกับ SAP ด้วยไฟล์ส่งออก ไม่เชื่อมต่อตรง และบังคับหลักฐานในโหมดอ้างเลขเอกสาร

ผู้ใช้ยืนยันวันที่ 8 ตุลาคม 2569 (M11 Q1–Q21) ว่าระบบทะเบียนเดิมของ ฝอจ. คือ SAP ซึ่งเชื่อมต่อจากระบบรับเรื่องไม่ได้ ระบบรับเรื่องจึงทำงานแยกจาก SAP และยังคงไม่ถือยอดเอง (ADR 0003): เจ้าหน้าที่ทำรายการใน SAP ก่อน แล้วบันทึกข้อเท็จจริง (จ่าย รับคืน ผลตรวจสภาพ การตัดสินผลตรวจขัดกัน การปิดส่วนต่างที่อ้างเลขเอกสาร) พร้อมเลขเอกสาร SAP และ**ไฟล์หลักฐาน**ที่ต้องแนบทุกครั้ง กองทะเบียนนำเข้าไฟล์ที่ส่งออกจาก SAP (รายการเอกสาร เลขเครื่อง ยอดคงเหลือ; CSV หรือ Excel) แล้วระบบ**กระทบยอดทะเบียน**: เทียบแต่ละบันทึกกับเอกสาร SAP ฉบับที่ส่งออกล่าสุด รายการที่ไม่ตรงเป็น**ส่วนต่างทะเบียน**ให้กองทะเบียนตัดสิน ไฟล์รอบหลังที่ตรงกันปิดส่วนต่างให้เอง ระบบไม่แก้ตัวเลขให้ตรงเอง

ทางเขียนผ่าน API (`api_confirmed`) มีเพียงสัญญาและระบบเดิมจำลองในเทสต์: หนึ่ง operation ต่อหนึ่ง idempotency key ผลที่ไม่ทราบต้องถามระบบเดิมก่อน ห้ามส่งซ้ำแบบไม่ตรวจ และ callback ซ้ำนับครั้งเดียว ทุกสภาพแวดล้อมปฏิเสธโหมดนี้จนกว่าจะมีสัญญา API จริง (G06)

## Considered Options

- **เชื่อม SAP ผ่าน API ตั้งแต่ M11:** ไม่เลือก เพราะ SAP เชื่อมต่อไม่ได้ และยังไม่มีสัญญาเรื่อง idempotency หรือการถามสถานะ
- **ให้เจ้าหน้าที่กดยืนยันทีละรายการว่า "ตรวจกับทะเบียนแล้ว":** ไม่เลือก เพราะตรวจย้อนไม่ได้ว่าตรวจจริง และเป็นงานซ้ำทุกรายการ
- **ระบบรับเรื่องถือยอดของตัวเองแยกจาก SAP:** ไม่เลือก เพราะขัดกับ ADR 0003 และจะมียอดทางการสองชุด
- **หลักฐานเป็นแค่รูปแบบเลขเอกสาร แนบไฟล์ไม่บังคับ:** ไม่เลือก ผู้ใช้เลือกให้บังคับแนบไฟล์ทุกครั้ง

## Consequences

- การบันทึกจ่าย รับคืน และผลตรวจในโหมดอ้างเลขเอกสารต้องมีไฟล์หลักฐานที่ผู้บันทึกเพิ่งแนบกับเรื่องนั้น ถ้าการกระทำถูกปฏิเสธ ไฟล์จะไม่ถูกเก็บ ไฟล์ที่สแกนไม่ผ่านจะเปิดส่วนต่างทะเบียนชนิด "หลักฐานใช้ไม่ได้"
- การเทียบใช้คู่ "เลขเอกสาร + รหัสทางการ (รหัสพัสดุ SAP)" ของ 1 ชนิดคู่กับรหัสทางการ 1 รหัส ของที่ยังไม่ผูกรหัสจะเทียบไม่ได้และขึ้นเป็นส่วนต่าง
- ระบบรู้ว่า "ไม่พบใน SAP" ได้เฉพาะวันที่ที่ไฟล์ครอบคลุมแล้ว ไม่นับวันทำการสุดท้ายของช่วงไฟล์ เพราะ SAP อาจผ่านรายการช้า บันทึกที่เกิน 7 วันและยังไม่มีไฟล์ใดครอบคลุมจะขึ้นเตือนเท่านั้น ไม่นับเป็นส่วนต่าง
- ส่วนต่างทะเบียนไม่เปิดเรื่องคืนและไม่บล็อกการปิดเรื่อง เพราะเรื่องคือบริการต่อเขต ส่วนต่างคือความถูกต้องของทะเบียน
- ความถูกต้องของการเทียบขึ้นกับการตั้งค่าที่ต้องยืนยันกับ ฝอจ. และเจ้าของ SAP: ประเภทการเคลื่อนไหว ชื่อคอลัมน์ ที่เก็บของ และรหัสทางการ
