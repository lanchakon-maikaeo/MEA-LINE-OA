# AI เสนอร่าง ส่วน backend ถืออำนาจและตรวจผลปลายทาง

ผู้ใช้ยืนยัน Q1–Q3 วันที่ 7 ตุลาคม 2569 ให้แยกการละเมิดสิทธิ์ออกจากความแม่นยำของ AI: AI ไม่มีอำนาจส่งเรื่อง อนุมัติ เปลี่ยนบทบาท หรืออ่านเรื่องผู้อื่น และต้องบังคับด้วย backend พร้อม negative tests ที่ผ่านทั้งหมด การยืนยันส่งเรื่องของผู้แจ้งยังจำเป็นและไม่ใช่การอนุมัติของเจ้าหน้าที่

เกณฑ์เปลี่ยนรุ่นคง JSON ≥98%, ประเภท ≥90%, ของ+จำนวน ≥85%, p95 ≤10 วินาทีบน held-out; ตรวจร่างจากเส้นทางใช้งานจริงและเปรียบเทียบ red-team ทั้งสองชุดกับ v4 โดยต้องไม่แย่ลง พร้อมรายงานการปนเปื้อนและ fallback ที่ยังเหลือ ไม่บังคับให้โมเดลสำรองแต่ละตัวสกัดถูกทุกข้อ และไม่ใช้คะแนนที่ดีขึ้นแทนหลักฐานสิทธิ์ ข้อแลกเปลี่ยนคือยอมรับว่าร่างอาจผิดและต้องตรวจทาน แต่ไม่ยอมให้โมเดลมีอำนาจธุรกรรม; ไม่ใช้โมเดลตรวจคำสั่งอีกตัวเป็นตัวตัดสินสิทธิ์

รอบนี้แก้และทดสอบในเครื่องโดยไม่สลับรุ่นที่เปิดอยู่ ไม่เปลี่ยนชุดทดสอบที่ล็อกไว้ ผลเก่าต้องประเมินใหม่เมื่อ guardrail หรือ gate เปลี่ยน

## การตีความที่ใช้ใน implementation

ใช้ heldout-v4 ที่ล็อกไว้แทน v1 ซึ่งเอกสารเดิมระบุว่าปนเปื้อนจากการพัฒนา harness แล้ว เปรียบเทียบ red-team แบบ application-to-application กับ v4 ที่รันใหม่ โดยรวมจำนวนและชนิดงานในร่างที่รอข้อมูลเพิ่มด้วย ไม่อนุมานว่า JSON เสียหรือไม่มีคำตอบคือการทำตามคำสั่งโจมตี และไม่ให้การปฏิเสธทุกคำขอทำให้ผ่านเกณฑ์

หลักฐานปลายทางแบ่งเป็นการ replay โมเดลจริงผ่านการเติมร่าง/คำถาม กับ integration tests ที่ควบคุมผลโมเดลเพื่อโจมตีสิทธิ์และการยืนยัน แต่ไม่มีการส่ง LINE จริงในการประเมินนี้ ผลผ่านชุดทดสอบไม่ได้รับประกันการต้านโจมตีที่ยังไม่เคยเห็นหรือใช้แทน production UAT
