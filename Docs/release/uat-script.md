# สคริปต์อบรมและตรวจรับ (UAT) รุ่น m13-rc1

ใช้อบรมตัวแทนเขตและเจ้าหน้าที่กองก่อน pilot และใช้เป็นแบบตรวจรับ G09 ใน [PROJECT.md](../../PROJECT.md) (E.10) ทุกขั้นใช้ข้อมูลจำลองบน staging ไม่ใช้รายการหรือบัญชี production

## ก่อนเริ่ม (ผู้ดูแลระบบ)

1. staging ใช้ release เดียวกับ candidate (`faoj status` และ `faoj releases` ตรงกับ `release-manifest.json`)
2. ข้อมูลจำลอง: `seed_staging` แล้วสร้างบัญชีเจ้าหน้าที่กองละหนึ่งบัญชีในหน้าแอดมิน กด "ทำได้ทุกงานในกอง"
3. LINE: ใช้ @894attlg บัญชีเดียวกับ production (C.2.3) เจ้าของ OA ตั้ง webhook ให้ชี้ staging ก่อนเริ่ม แล้วใส่ LINE user ID ของผู้เข้าร่วมใน `LINE_ALLOWED_RECIPIENTS` บอทตอบเฉพาะคนในรายการ ระหว่างนี้คนนอกรายการที่ทักมาจะไม่ได้คำตอบ
4. ตัวเลือกระบบตามที่ตกลงในรอบ pilot (หน้า "ตัวเลือกระบบ") และคลังคำตอบที่ ฝอจ. รับรองแล้ว
5. ช่องทางสำรอง: เบอร์ตามหัวข้อและลิงก์แบบฟอร์มสำรองใน `compose.env`
6. ผู้สังเกตหนึ่งคนจดผลในตารางท้ายเอกสาร

บทบาทในการซ้อม: ผู้แจ้ง (มือถือ LINE), เจ้าหน้าที่กองเจ้าภาพ (เว็บ), แอดมิน (เว็บ) และผู้สังเกต

## ส่วนที่ 1 อบรม (ประมาณ 45 นาที)

- เปิดหน้า "สาธิตการใช้งาน" ในเว็บแล้วเดินตามทัวร์หนึ่งรอบ
- งานสามแบบ: เบิก คืน แจ้งปัญหา/ข้อเสนอแนะ แต่ละแบบจบที่ไหนและใครกดอะไร
- ผู้แจ้งเห็นเฉพาะเรื่องของตัวเอง แม้อยู่เขตเดียวกัน เจ้าหน้าที่เห็นเฉพาะเรื่องของกองตัวเอง
- ข้อความจากบอทที่ต้องกดตอบ: ขอข้อมูลเพิ่ม ยืนยันรับของ ยืนยันผลแก้ไข ข้อความอื่นกด "เรื่องของฉัน" ดูเองได้
- ระดับความเร่งด่วนและกองเจ้าภาพเป็นข้อเสนอของระบบ เจ้าหน้าที่เลือกต่างได้เมื่อบอกเหตุผล
